# 直连模式整体实现架构

> 组件图、配置清单、服务清单的**事实速查**。设计原因见《直连桥单实例路由架构设计》，
> 使用与排错见根目录 README 与《排错手册》。

## 组件图

```
客户浮窗（任意网络）
   │
   ▼
Chatwoot（chat.blueaisoft.com，云端/205）
   │ AgentBot 回调：HMAC(bot_secret, ts.body) + X-Chatwoot-Timestamp
   ▼ http://192.168.0.206:8300/webhook/chatwoot
bridge.mjs 单实例（206:8300，launchd com.blueaisoft.cw-oc-bridge）
   │ 验签(双格式) → 去重(持久化) → 路由(INBOX_ROUTE_MAP) → 并发控制(4全局/2品牌/队列100)
   │ → 会话锁 → OpenClaw WS RPC(loopback 18789) → 30s超时降级三件套
   ▼
OpenClaw Gateway（loopback）
   ├─ agent:bluewms-support（inbox 7，zai-flash/glm-5.3-Flash，thinking low）
   ├─ agent:zhuofeng-support（inbox 8，同模型）
   └─ agent:main（个人助理，不承接客户）
   ▼ 回复经桥发送（品牌 bot token 身份）→ 客户浮窗
```

## 配置文件

| 文件 | 内容 |
|---|---|
| routes.json | secrets 池 + inboxMap（inbox→agent/botToken），支持热重载 |
| launchd plist | 端口/路由文件路径/并发参数/超时/Gateway token |
| OpenClaw openclaw.json | agents.entries（各 Agent 的 workspace/model/thinking） |

## 关键参数

| 参数 | 值 | 说明 |
|---|---|---|
| AGENT_TIMEOUT_MS | 30000 | AI 生成超时，超时走降级三件套 |
| MAX_GLOBAL_CONCURRENCY | 4 | 全局并发 |
| MAX_PER_INBOX_CONCURRENCY | 2 | 单品牌并发 |
| MAX_QUEUE_SIZE | 100 | 队列容量，满则直接降级 |
| SESSION_QUEUE_TIMEOUT | 60s | 同会话排队上限 |
| SLOW_REQUEST_LOG_MS | 20000 | 慢请求告警阈值 |
