# 直连模式整体实现架构（v1.1 实施版）

**版本**：v1.1
**日期**：2026-11-17
**定位**：Chatwoot 与 OpenClaw 之间的唯一连接层（替代原 FastAPI 通道层）
**配套文档**：《直连桥单实例路由架构设计》（§ 编号引用同该文档）

## 一、总体架构

```
                        客户（任意网络）
                              │ 浮窗消息
                              ▼
┌─────────────────────────────────────────────────────────────┐
│ Chatwoot（云端 chat.blueaisoft.com，客户触达与存储）          │
│   AgentBot 机制：各品牌 bot 的 outgoing_url 统一指向桥       │
│   POST http://192.168.0.206:8300/webhook/chatwoot           │
│   （携带 HMAC-SHA256 签名）                                  │
└──────────────┬──────────────────────────────────────────────┘
               │ HTTP webhook（LAN 直达）
               ▼
┌─────────────────────────────────────────────────────────────┐
│ bridge.mjs 单实例（206 本机 :8300，launchd 常驻）             │
│                                                             │
│  接收管道                                                   │
│  ① 验签：WEBHOOK_SECRETS 列表匹配（恒定时间比较）            │
│  ② 过滤：event=message_created / incoming / 非 private      │
│  ③ 幂等去重：message_id 水位（内存 5 分钟窗 + SQLite 持久化） │
│  ④ 路由解析：INBOX_ROUTE_MAP[inbox] → {agentId, botToken}   │
│     未映射 inbox → ignored + 私有备注告警（不处理）           │
│                                                             │
│  并发控制（§4 有界化）                                       │
│  ⑤ 全局并发信号量（默认 4）                                  │
│  ⑥ 每品牌并发上限（默认 2）                                  │
│  ⑦ 有界队列（默认 100；会话排队上限 60s）                     │
│     队列满/排队超时 → 降级三件套（§7）                        │
│                                                             │
│  执行                                                       │
│  ⑧ 会话锁：同会话串行（尾随队列），跨会话并行                 │
│  ⑨ WebSocket RPC → OpenClaw Gateway（loopback 18789）        │
│     sessions.create/send → 指定 Agent 生成回复               │
│     事件流三重过滤（runId / collector 按轮注册 / sessionKey） │
│     delta 追加 / 快照覆盖 / replace 替换 三种语义             │
│  ⑩ 超时 30s / 失败 → 降级三件套（§7）：                       │
│     兜底文案 + pending→open 转人工 + 私有备注                │
│     迟到回复一律丢弃（防双回复）                              │
│                                                             │
│  回复                                                       │
│  ⑪ Chatwoot REST API 发送（按路由 botToken 身份）            │
│                                                             │
│  持久化与观测（§9）                                          │
│  • SQLite：processed_messages（去重水位/状态）+ stats_daily  │
│  • 重启恢复扫描：中断 >5 分钟的消息 → 告警 + 私有备注         │
│  • 路由热重载：SIGHUP 重读路由表（加品牌零重启）              │
│  • /healthz（内网监控）/ /stats（loopback only）             │
│  • 兜底限流：每 inbox 每分钟 ≤3 条兜底文案（防风暴）          │
└──────────────┬──────────────────────────────────────────────┘
               │ WebSocket RPC（loopback，零暴露）
               ▼
┌─────────────────────────────────────────────────────────────┐
│ OpenClaw Gateway（127.0.0.1:18789，launchd 常驻）            │
│                                                             │
│  Agent 运行时（多角色，按 session key 路由）：                │
│  ┌────────────────┬────────────────────────────────────┐   │
│  │ Agent          │ 职责 / inbox                        │   │
│  ├────────────────┼────────────────────────────────────┤   │
│  │ bluewms-support│ BlueWMS 客服（inbox 7）             │   │
│  │ zhuofeng-support│ 卓风客服（inbox 8）                 │   │
│  │ main           │ 个人助理（不承接客户流量）           │   │
│  └────────────────┴────────────────────────────────────┘   │
│  每角色独立 workspace：                                      │
│   AGENTS.md（人设/诚实原则/安全边界/升级判断/输出格式）       │
│   未来：知识库文档 / knowledge 插件 / MCP 工具（只读）        │
│                                                             │
│  模型：zai-flash/glm-5.3-Flash（thinking=low）              │
│  fallback：zai/glm-5.3-flashx                               │
└─────────────────────────────────────────────────────────────┘
```

## 二、组件清单与职责边界

| 组件 | 形态 | 职责 | 明确不做 |
|---|---|---|---|
| Chatwoot（云端） | Docker（云服务器） | 客户触达、消息存储、人工工作台、handoff（pending→open） | AI 推理 |
| **bridge.mjs**（本方案核心） | Node 24 单文件，launchd 常驻 | 验签/过滤/去重/路由/并发控制/协议翻译/超时兜底/回复身份/观测 | 业务逻辑、知识、工具调用 |
| OpenClaw Gateway | Node，launchd 常驻（loopback） | Agent 运行时：推理/会话记忆/人设/未来工具编排 | 不直接调 Chatwoot |
| Agent workspace | 目录（AGENTS.md 等） | 角色定义与知识载体 | — |
| SQLite + JSONL | 本地文件 | 去重水位、统计落盘、token 成本 | — |

**职责红线**：业务智能只活在 OpenClaw 侧；bridge 永远不懂“客服业务”，只懂“搬运 + 守护”。

## 三、连接与凭据

| 连接 | 方向 | 协议/端点 | 凭据 |
|---|---|---|---|
| Chatwoot → bridge | 入 | HTTP webhook（LAN） | HMAC secret（WEBHOOK_SECRETS） |
| bridge → OpenClaw | 出 | WebSocket RPC ws://127.0.0.1:18789 | Gateway token |
| bridge → Chatwoot | 出 | HTTPS REST | 各品牌 Agent Bot Access Token（路由表） |

安全设计：Gateway 永远 loopback；8300 仅 LAN 可达；/stats 仅 loopback；bot token/secret 不进日志与 /stats；日志正文截断 30 字符。

## 四、配置清单

```bash
# 路由（inbox → agent + 发送身份）
INBOX_ROUTE_MAP={"7":{"agent":"bluewms-support","botToken":"<客服Agent token>"},
                 "8":{"agent":"zhuofeng-support","botToken":"<卓风Agent token>"}}
# 验签
WEBHOOK_SECRETS=["<secret>"]
# 并发与队列（§4）
MAX_GLOBAL_CONCURRENCY=4
MAX_PER_INBOX_CONCURRENCY=2
MAX_QUEUE_SIZE=100
SESSION_QUEUE_TIMEOUT=60
# 超时与告警
AGENT_TIMEOUT_MS=30000
SLOW_REQUEST_LOG_SECONDS=20
# 存储与日志
BRIDGE_DB=data/bridge.db
TOKEN_USAGE_LOG=data/token_usage.jsonl
# OpenClaw
OPENCLAW_GATEWAY_URL=ws://127.0.0.1:18789
OPENCLAW_GATEWAY_TOKEN=<gateway token>
OPENCLAW_AGENT_ID=bluewms-support   # 默认路由（未映射 inbox 兜底，通常不用）
```

## 五、关键机制速查

| 机制 | 设计 | 文档引用 |
|---|---|---|
| 双回复防护 | 去重（持久化水位）+ 会话锁 + 迟到回复丢弃 | §5.3 / §9 |
| 故障兜底 | 30s 超时/失败 → 降级三件套（文案+转人工+私有备注） | §7 |
| 兜底风暴防护 | 每 inbox 每分钟 ≤3 条兜底文案限流 | §9 |
| Gateway 故障恢复 | 熔断：连续 3 失败 → 300s 全兜底 → 半开探测 | §10 |
| 重启安全 | 去重持久化 + 恢复扫描（中断消息告警备注，不自动补发） | §9 |
| 品牌扩展 | 路由热重载（SIGHUP），零重启零丢失 | §9 |
| SPOF 声明 | 单点故障，水平扩展列 Phase 3+（共享去重/分布式锁/队列分区） | §2 |

## 八、验收基线（v1.1 §12 摘要）

| 指标 | 目标 |
|---|---|
| 时延 | P50 ≤10s / P95 ≤25s / P99 ≤30s |
| 兜底率 | ≤5%（分母=观察期全部客户消息，观察 7 天） |
| 断线恢复 | 100% 兜底 + 恢复后 60s 内主链路回归 |
| 重复事件 / 迟到回复 / 双发 / 串线 | 全部 = 0 |
| 降级三件套完整率 | 100% |
| 新品牌接入 | 改路由表 + 热重载 ≤1 分钟，零丢失 |
